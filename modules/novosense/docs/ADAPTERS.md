## DIY
Firmware: firmware/novo_i2c/novo_i2c.ino. ESP32-C3 GPIO8/9 (Board-Strapping beachten), Pro Micro SDA/SCL laut Pinout. Web-App, Verbindung & Diagnose, Adapter wählen, Modell wählen, Port wählen. HELLO muss NOVO-I2C-5 liefern, INFO identifiziert ESP32-C3 bzw. ATmega32U4. Gemeinsame ASCII-Zeilen mit Sequenz-ID, Antwort OK/ERR. R liest, M startet nur NSA2300-Einzelmessung, A maskiert NSA2860X-AFE-RAM. Keine beliebigen Writes.

## Originalboard (Windows/Linux mit geeignetem USB-RS485-Adapter)
Web Serial bietet keine Mark-/Space-Parität. Lokaler Dienst nutzt pyserial und serviert exakt dieselbe Web-App aus dem Repository. Windows/Linux-Python 3.10+, Treiber und USB-RS485-Hardware mit Mark/Space erforderlich. macOS und USB-Timing nicht validiert; Mark/Space ist dort ggf. nicht möglich. Offizielle GUI schliessen.

1. Repo als ZIP herunterladen und entpacken oder git clone https://github.com/Vadergit/NOVOSENSE-SSC-Calibration-Web-App.git
2. Im Repo-Ordner: python -m pip install pyserial
3. python native/evm_service.py --list
4. Beispiel Windows: python native/evm_service.py --board evm --serial COM3 --output voltage
   Linux: python3 native/evm_service.py --board evm --serial /dev/ttyUSB0 --output voltage
   Für Stromausgang: --output current. Für CAL32: --board cal32 --address 0x80.
5. Chrome/Edge: http://127.0.0.1:8765/ öffnen. Verbindung & Diagnose, passendes Originalboard wählen. Board verbinden. Board-Version separat prüfen.
6. Nur mit richtigem DUT und Output-Modus: beim EVM OWI aktivieren (Power-Cycle) bestätigen, Sensor identifizieren. Erst danach Register-/Messwertfunktionen. Der 0x17-Leseframe mit Register, Anzahl, Ausgangsmodus ist eine experimentelle Interpretation der Hersteller-Befehlstabelle; Rückgabe wird auf Adresse, Länge, Funktion, Status, CRC und Datenmenge geprüft. Keine automatische Wiederholung.
7. USB-Protokoll exportieren, Fehler analysieren. Trennen, Dienst mit Ctrl+C beenden.

Der Dienst bindet ausschliesslich 127.0.0.1, akzeptiert nur gleiche Origin und feste Befehle, keine beliebigen Register-Schreibbefehle. CAL32 unterstützt hier nur Versionsabfrage. Keine Online-Web-App mit Cross-Origin-Zugriff auf lokale Ports.

### 32CAL direkt im Browser
32CAL nutzt 8N1 und kann alternativ ohne nativen Dienst direkt via USB-RS485 mit Chrome/Edge verbunden werden. MCU-Adresse vor dem Öffnen wählen (0x80–0xF0, Standard 0x80). Versionsframe 0x00, Adress-/Längen-/CRC-/Statusprüfung. Kanalwahl, Sensorzugriff und Programmierung sind noch nicht freigegeben. Native CLI bleibt als Diagnosealternative vorhanden.

Detailed DIY wire protocol: [PROTOCOL.md](PROTOCOL.md). Binary firmware artifacts are generated by the firmware workflow.

Aktuelle Labor-Testsequenz: [LAB-TEST.md](LAB-TEST.md). OEM-Boards bleiben nur lesend/Diagnose.
